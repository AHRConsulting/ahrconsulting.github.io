Scenarios

Steps

  • Order: steps go Given, When, then Then. And continues the step before it. Given is optional, and the last step is a check.
  • Callbacks can be synchronous or Task-returning, and can take the run's cancellation token.
  • Ordinary assertions work in every step: xUnit, NUnit, MSTest and TUnit asserts, Shouldly, FluentAssertions and Playwright's Expect.
    • A failed check in Then or And makes that check unsatisfied, and the other checks still run.
    • A failed assertion in Given or When stops the scenario.
    • Any other exception is an execution error, and the report names the step that stopped.
  • Inline scenarios run once. Define each one inside its test.

Acting again after a check

A When after a Then starts the next action:

return Scenario.Define("A basket's total follows what is in it")
    .Given("An empty basket", () => basket = new Basket())
    .When("A £7 book is added", () => basket.Add(7m))
    .Then("The total is £7", () => Assert.Equal(7m, basket.Total))
    .When("The book is removed", () => basket.Remove(7m))
    .Then("The total is zero", () => Assert.Equal(0m, basket.Total))
    .VerifyAsync();

Checking what a When returned

A When that returns a value hands it to the checks that take a parameter of its type, so the scenario needs no local to hold it:

return Scenario.Define("A connected reader downloads and saves a document")
    .Given("An online reader with an empty cache", cache.ClearAsync)
    .When("The reader opens the handbook", token => reader.OpenAsync("handbook", token))
    .Then("The expected document is returned", (DocumentReadResult result) => Assert.Equal(expected, result.Document))
    .And("The downloaded document is saved for later", async token =>
        Assert.Equal(expected, await cache.FindAsync("handbook", token)))
    .And("The web source is contacted once", () => Assert.Equal(1, source.DownloadCalls))
    .VerifyAsync();

Capturing the value in a local, as getting started does, works too, and suits a converted test or a value several steps read.

Checking an exception

WhenThrows<T> passes only when its work throws exactly T, and the checks after it take the exception. WhenThrowsAny<T> also accepts a type derived from T.

return Scenario.Define("A charge of nothing is refused")
    .Given("A basket", () => basket = new Basket())
    .WhenThrows<ArgumentOutOfRangeException>("Nothing is charged", () => basket.Charge(0m))
    .Then("The refusal names the amount", (ArgumentOutOfRangeException refusal) => Assert.Equal("amount", refusal.ParamName))
    .VerifyAsync();

Parameterised tests

Keep the framework's own parameterised tests: [Theory] with [InlineData] in xUnit, [TestCase] in NUnit, [DataRow] in MSTest or [Arguments] in TUnit. Only the test's body becomes a scenario. Give it the same name for every row, and the report shows the rows as one journey, with a table of examples.

[Theory]
[InlineData(7, 5, 12)]
[InlineData(0, 0, 0)]
public Task ATotalAddsItsLines(int first, int second, int total)
{
    Basket basket = new();
    return Scenario.Define("A basket's total adds its lines")
        .Given($"Lines of £{first} and £{second}", () => { basket.Add(first); basket.Add(second); })
        .When("The total is read", () => basket.Total)
        .Then($"It is £{total}", (decimal read) => Assert.Equal(total, read))
        .VerifyAsync();
}

Reusable steps

When tests share steps, write each step once and use it by name. Steps are plain C#: static members of a class, over a context the scenario creates fresh for each run.

[Fact]
public Task AReaderOpensASavedDocument() =>
    Scenario.Define<ReadingContext>("A reader opens a saved document")
        .Given(ReadingSteps.ASavedDocument("handbook"))
        .When(ReadingSteps.TheReaderOpens("handbook"))
        .Then(ReadingSteps.TheDocumentIsShown("handbook"))
        .VerifyAsync();

The steps class uses the protected factories of ScenarioSteps<TContext>. A step that differs by a value is a method that builds its own name:

internal sealed class ReadingSteps : ScenarioSteps<ReadingContext>
{
    public static ScenarioAction<ReadingContext> ASavedDocument(string id) =>
        CreateActionStep($"'{id}' is saved on the device", context => context.Cache.Seed(new Document(id, "Field handbook")));

    public static ScenarioAction<ReadingContext> TheReaderOpens(string id) =>
        CreateActionStep($"The reader opens '{id}'", async (context, token) =>
            context.Result = await new DocumentReader(context.Connectivity, context.Source, context.Cache).OpenAsync(id, token));

    public static ScenarioExpectation<ReadingContext> TheDocumentIsShown(string id) =>
        CreateAssertionStep($"'{id}' is shown", context => Assert.Equal(id, context.Result?.Document?.Id));
}
Factory For
CreateActionStep Setup or work
CreateAssertionStep Ordinary assertions
CreateExpectationStep An explicit ExpectationResult
CreateThrowsStep<T> Work that should throw T

The context is an ordinary class holding what the steps share:

internal sealed class ReadingContext : IDevice
{
    public IConnectivity Connectivity { get; set; } = new FakeOnlineConnectivity();

    public FakeInMemoryDocumentCache Cache { get; } = new();

    public FakeDocumentSource Source { get; } = new(new Document("handbook", "Field handbook"));

    public DocumentReadResult? Result { get; set; }
}

Steps shared across features

Some steps cut across features, such as taking the device offline. Write them once for an interface:

public interface IDevice
{
    IConnectivity Connectivity { get; set; }
}

internal sealed class DeviceSteps : ScenarioSteps<IDevice>
{
    public static ScenarioAction<IDevice> TheDeviceIsOffline { get; } =
        CreateActionStep("The device is offline", device => device.Connectivity = new FakeOfflineConnectivity());

    public static ScenarioAction<IDevice> TheDeviceIsOnline { get; } =
        CreateActionStep("The device is online", device => device.Connectivity = new FakeOnlineConnectivity());
}

Any scenario whose context implements the interface can use them alongside its own steps, as ReadingContext does above:

[Fact]
public Task AnOfflineReaderOpensASavedDocument() =>
    Scenario.Define<ReadingContext>("An offline reader opens a saved document")
        .Given(DeviceSteps.TheDeviceIsOffline)
        .And(ReadingSteps.ASavedDocument("handbook"))
        .When(ReadingSteps.TheReaderOpens("handbook"))
        .Then(ReadingSteps.TheDocumentIsShown("handbook"))
        .VerifyAsync();

A scenario whose context doesn't implement the interface doesn't compile.

The analyzers report common mistakes as you type, such as a scenario that is never verified.
