Running in CI

Build the report after the tests:

dotnet test
dotnet assurance report

Run the report step even when dotnet test fails, so the report shows what failed. dotnet assurance report exits with 2 when the report shows failures, and with 1 when it couldn't run: see exit codes.

One run across shards

When the tests run in several jobs, give them one run ID, so every shard writes to the same run. Use the pipeline's own build number:

export ASSURANCE_RUN_ID=build-1234

Share the report

Upload report.html and the attachments folder beside it as one artifact. The report works offline, so anyone can open it from the download.

TRX and other test results

Assurance doesn't replace or interfere with TRX or other test result files, and scenarios run side by side with your other tests. Test results record outcomes for CI tools; Assurance records the scenarios behind them, for people to read.
